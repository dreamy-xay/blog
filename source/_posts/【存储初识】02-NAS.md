## 一、NAS（网络附加存储）

### 1 概述
 
NAS（Network Attached Storage，网络附加存储）是一种将分布、独立的数据整合为大型、集中化管理的数据中心，以便于对不同主机和应用服务器进行访问的技术。按字面理解，NAS就是连接在网络上、具备数据存储功能的装置，因此也被称为“网络存储器”。

NAS被定义为一种专用数据存储服务器，包括存储器件（如磁盘阵列、CD/DVD驱动器、磁带驱动器或可移动存储介质）和内嵌系统软件，可提供跨平台文件共享功能。它以数据为中心，将存储设备与服务器彻底分离，集中管理数据，从而释放带宽、提高性能。其成本远低于使用服务器存储，而效率却远高于后者。

### 2 核心特点

- 通过网络（通常是以太网）连接，拥有自己的节点，无需应用服务器干预即可让用户在网络上存取数据
- 具备文件系统和IP地址，可理解为“网上邻居的共享磁盘”
- 支持多种协议（如NFS、CIFS/SMB、FTP、HTTP等），兼容各种操作系统
- 通过任何一台工作站，使用浏览器即可对NAS设备进行直观方便的管理
- NAS是功能单一的精简型电脑，架构上不像个人电脑那么复杂，外观上像家电产品，只需电源与简单的控制钮
- NAS必须具备两个物理条件：能够访问卷或物理磁盘；具有接入以太网的能力（即以太网卡）
- 一台普通主机就可以充当NAS，只要它有自己的磁盘和文件系统，并对外提供访问其文件系统的接口（如NFS、CIFS等）

### 3 优缺点

**优点：**
- **成本低**：前端只需以太网接口即可，相比SAN所需的FC适配卡和光纤交换机，成本大幅降低
- **节省服务器资源**：NAS可将文件服务从应用服务器上卸载下来，减轻主机的CPU和内存负担
- **部署简单、扩展性强**：利用以太网，可扩展性强且容易部署
- **共享能力强**：可在一台盘阵上实现多台客户端的共享访问，包括同时访问某个目录或文件
- **协议丰富**：提供多种协议访问数据，而SAN只能使用SCSI协议访问
- **并发处理能力强**：经过特别优化的NAS系统，可以同时并发处理大量客户端的请求
- **简化系统冗余**：多台主机可同时挂载NFS上的目录，将多个并行处理转化为单一实例

**缺点：**
- **一般情况下速度不及SAN**：NAS架构使用以太网和TCP/IP代替内存进行通信，增加了CPU指令周期，且以太网速度慢于内存
- **协议差异带来的性能开销**：TCP/IP逻辑和网卡驱动程序消耗额外的CPU资源
- **部分协议存在局限性**：如NFS缺乏加密和授权功能（v4以前仅靠IP/主机名控制），SMB传输效率有时不太稳定

## 二、NAS常见共享访问协议

### 1 NFS（网络文件系统）

NFS是一种分布式文件系统协议，由Sun公司开发，于1984年发布，最新版本NFSv4.2于2016年发布。它基于ONC RPC协议，是一个开放标准的RFC协议。

**特点：**
- 通常用于Unix/Linux/FreeBSD等类Unix系统，macOS和Windows也提供NFS实现
- 内核直接支持，部署简单、运行稳定，协议简单、传输效率高

**缺点：**
- 缺乏加密授权功能，仅靠IP地址或主机名控制挂载权限（NFSv4以前），对具体目录和文件无法进行ACL权限控制
- Windows客户端挂载NFS共享时，中文文件名可能显示为乱码（因UTF-8支持问题）

### 2 SMB / Samba（服务器消息块）

SMB是微软设计的专用协议，用于Windows主机间的文件与打印共享。Samba是Andrew Tridgell通过逆向工程在Linux上实现的SMB/CIFS兼容协议，实现了Windows与Linux之间的文件共享。

**特点：**
- 兼容性极好，在Windows、Linux、macOS等各平台获得广泛支持
- 电视、电视盒子等设备默认支持，可用于远程播放电影、音乐和图片
- 提供端到端加密、安全性高，配置选项丰富，支持ACL和多用户认证模式

**缺点：** 
- 传输效率稍低，速度不太稳定，会有波动

### 3 FTP（文件传输协议）

FTP是TCP/IP应用层的基础协议，通常使用21端口，负责将文件从一台计算机传输到另一台计算机。第一版FTP协议于1971年发表为RFC 114。

## 三、NAS与SAN的对比

| 对比维度     | NAS（网络附加存储）              | SAN（存储区域网络）          |
| :--------: | :------------------------: | :--------------------: |
| **本质**   | 一个设备（专有文件服务器）            | 一个网络系统               |
| **核心功能** | 文件级别的共享访问                | 块级别的数据存储             |
| **通俗理解** | 网络上的文件系统                 | 网络上的磁盘               |
| **访问协议** | NFS、CIFS/SMB、FTP、HTTP等   | SCSI（FC或iSCSI）       |
| **传输网络** | 以太网                      | 光纤通道（FC）或以太网（iSCSI）  |
| **成本**   | 较低（以太网卡和交换机便宜）           | 较高（FC适配卡和光纤交换机昂贵）    |
| **速度**   | 一般情况下较慢（受以太网和TCP/IP开销影响） | 一般较快（FC硬件处理，速度高于以太网） |
| **共享能力** | 强，多客户端可同时访问同一目录/文件       | 弱，需集群管理软件才能共享LUN     |
| **文件系统** | 有完整的文件操作和管理系统            | 无文件系统，仅做数据管理         |

**补充说明：**
- NAS和SAN并非相互排斥，可以共存于同一系统网络中。NAS产品也能通过SAN连接到存储设备。
- 在大量随机小块I/O、缓存命中率极低的环境下，后端磁盘成为瓶颈时，NAS可能不比SAN慢，甚至因优化的并发I/O设计而表现更优。
- iSCSI作为沟通IP与SCSI的新协议，使SAN可以在以太网上运行，被视为影响SAN发展的重要事件。

## 四、三种存储方案对比

|   对比维度   |      DAS（直连式存储）       |  NAS（网络附加存储）  |    SAN（存储区域网络）     |
| :------: | :-------------------: | :-----------: | :----------------: |
| **连接方式** | 通过SCSI或FC接口直接连接到一台计算机 | 通过以太网连接到一群计算机 | 通过光纤交换机或以太网连接到多台主机 |
| **访问级别** |          块级别          |     文件级别      |        块级别         |
| **共享能力** |       仅挂载的主机可访问       |   多客户端可共享访问   |     需特殊软件才能共享      |
| **文件系统** |         由主机管理         |    自带文件系统     |       无文件系统        |

<strong style="color: #db8ef7;">[1]</strong> **SAN（Storage Area Network，存储区域网络）：** 一种在服务器和存储器之间用作I/O路径的专用高速网络。基于光纤通道技术，将多个存储设备连接起来，再与服务器网络连接，实现多点对多点的数据管理。SAN包括面向块（SCSI）和面向文件（NAS）的存储产品。
<strong style="color: #db8ef7;">[2]</strong> **DAS（Direct Attached Storage，直连式存储）：** 将存储设备通过SCSI接口或FC接口直接连接到一台计算机上的存储方式，只有所挂载的主机才能访问，不属于网络存储。
<strong style="color: #db8ef7;">[3]</strong> **LUN（Logical Unit Number，逻辑单元号）：** 在SAN环境中，用于标识存储设备中的逻辑单元，是主机访问存储资源的基本单位。
