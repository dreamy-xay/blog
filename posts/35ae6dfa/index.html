【存储初识】05-内核文件系统

发表于2026-07-06|更新于2026-07-08|存储基本概念
|字数总计:3.7k|阅读时长:11分钟|阅读量:

一、文件系统的基本组成

文件系统负责将用户文件持久化存储到磁盘，其基本数据单位是文件。Linux 遵循“一切皆文件”的设计哲学，普通文件、目录、块设备、管道、Socket等均由文件系统统一管理。文件系统会为每个文件分配两个数据结构：

核心数据结构 作用 存储位置 关键点
inode（index node，索引节点） 记录文件元信息（大小、权限、时间戳、磁盘位置等） 磁盘（占用空间） 文件的唯一标识，一一对应
dentry（directory entry，目录项） 记录文件名、inode 指针及目录层级关系 内存（内核缓存） 用于加速路径查找，与 inode 是多对一关系（硬链接即如此）

✍️ 易混淆点
●目录是存储于磁盘的文件（内容为子目录/文件列表）
●目录项是内核缓存在内存中的数据结构，用以提升查询效率

磁盘读写单元：

  • 物理最小单元：扇区（512B）
  • 文件系统逻辑单元：数据块（Linux 默认为 4KB，即 8 个扇区）
目录项和索引关系图

磁盘分区结构（格式化后）：

  • 超级块：存储全局信息（块总数、空闲块等），挂载时载入内存。
  • inode 区：存放 inode，文件访问时载入内存。
  • 数据块区：存放文件/目录的实际数据。

二、虚拟文件系统

为屏蔽底层不同文件系统的差异，操作系统引入虚拟文件系统（Virtual File System，VFS）层，为用户进程提供统一的系统调用接口（如 open、read、write）。

用户空间、系统调用、虚拟文件系统、缓存、文件系统以及存储之间的关系图

文件系统分类（基于存储位置）：

  • 磁盘型：Ext2/3/4、XFS等（数据持久化在硬盘）
  • 内存型：/proc、/sys等（数据存储在内存，反映内核状态）
  • 网络型：NFS、SMB等（访问其他主机数据）

文件系统需挂载到某个目录（如根目录 /）才能使用。

三、文件的使用

标准操作流程（用户视角）：

写入到磁盘的流程图

核心概念：文件描述符与打开文件表

  • 操作系统为每个进程维护一张打开文件表，表项即文件描述符（fd）。
  • 该表跟踪每个打开文件的状态：
    • 文件指针：当前读写位置（进程独有）
    • 打开计数器：记录有多少进程打开了该文件，计数归零时系统才真正关闭文件
    • 磁盘位置：缓存在内存（避免频繁 I/O）
    • 访问权限：创建、只读、读写、添加等模式

读写差异：

  • 用户习惯按字节操作，操作系统按数据块读写。
  • 文件系统负责屏蔽这一差异，确保读/写 1 字节时，实际涉及整块数据的加载/修改并回写。

四、文件的存储方式

文件数据在磁盘上的存放方式与程序在内存中的组织类似，分为连续空间和非连续空间两种。

1 连续空间存放方式

连续空间存放方式要求文件在磁盘上占据连续物理空间，需预先确定文件大小，并在文件头（类似 inode）中记录起始块位置和长度，从而一次寻道即可读写整个文件。

连续空间存放方式
  • 优点：读写效率极高（仅需一次寻道）。
  • 缺点：产生磁盘碎片，且文件长度不易扩展（需移动大量数据）。

2 非连续空间存放方式

非连续空间存放方式分为链表方式和索引方式。

2.1 链表方式

链表方式通过非连续存放消除磁盘碎片、提升空间利用率并支持动态扩展，具体实现分为隐式链表和显式链接两种。

2.1.1 隐式链表

隐式链表在每个数据块中预留一个指针空间，用于存放下一个数据块的位置，同时在文件头（类似 inode）中记录首块和末块的位置。访问文件时，需从链头开始沿指针顺序遍历，从而通过这种不连续存放的方式找到所有数据块。

非连续空间存放方式-链表方式
  • 优点：消除了磁盘碎片，提高了磁盘空间利用率，且支持文件长度的动态扩展。
  • 缺点：只能通过指针顺序访问文件，无法高效支持随机访问；数据块中的指针消耗了部分存储空间；稳定性较差，一旦指针损坏或丢失，后续数据将无法读取。
2.1.2 显式链接

显式链接将用于链接文件各数据块的指针统一存放在内存中的一张链接表中，该表在整个磁盘仅设置一张，称为FAT（File Allocation Table，文件分配表）。表项中存放指向下一个数据块的指针，通过遍历链表即可找到文件的所有数据块。

文件分配表
  • 优点：查找记录在内存中进行，检索速度快，支持直接访问，且大大减少了访问磁盘的次数。
  • 缺点：FAT 表需常驻内存，不适用于大磁盘（例如 200GB 磁盘、1KB 块大小，FAT 表需占用约 800MB 内存）。

2.2 索引方式

索引方式为每个文件创建一个索引数据块，其中存放指向文件数据块的指针列表（类似书的目录）。文件头（inode）需包含指向该索引数据块的指针，创建文件时索引块指针初始为空，写入数据时再从空闲空间中分配块并填充索引条目。

非连续空间存放方式-索引方式
  • 优点：无碎片，支持顺序和随机读写，文件增删改方便。
  • 缺点：小文件也需要额外分配索引块来存储指针，带来一定的存储开销。

针对大文件索引块放不下的问题，衍生出链式索引块和多级索引块两种组合方案。

2.2.1 链式索引块

在索引数据块中预留一个指针，用于指向下一个索引数据块，从而将多个索引块链接起来。

链式索引块

缺点：存在指针损坏导致后续数据丢失的风险（与链表方式类似）。

2.2.2 多级索引块

通过一个索引块来存放多个索引数据块的地址，形成“一级索引指向二级索引，二级索引指向数据块”的层层嵌套结构。

多级索引块

2.3 不同文件实现方式的对比

方式 访问磁盘次数 优点 缺点
顺序分配 需访问磁盘 1 次 顺序存取速度快，当文件是定长时可以根据文件起始地址及记录长度进行随机访问 要求连续的存储空间，会产生外部碎片，不利于文件的动态扩充
链表分配 需访问磁盘 n 次 无外部碎片，提高了外存空间的利用率，动态增长较方便 只能按照文件的指针链顺序访问，查找效率低，指针信息存放消耗内存或磁盘空间
索引分配 m 级需访问磁盘 m+1 次 可以随机访问，易于文件的增删 索引表增加存储空间的开销，索引表的查找策略对文件系统效率影响较大

3 Unix（Ext2/3）混合实现

早期 Unix 文件系统（如 Ext2/3）综合了上述方式的优点，采用混合索引（直接指针 + 多级间接索引）的实现方案。

Unix 多级索引

其核心是 inode 中包含 13 个指针，根据文件大小动态选择存储方式：

  • 10 个直接指针：直接指向数据块。当文件所需数据块少于 10 块时，直接通过指针访问，省去索引块开销，非常适合小文件。
  • 第 11 个指针：指向一级间接索引块（索引块中存数据块地址）。
  • 第 12 个指针：指向二级间接索引块（索引块中存一级索引块的地址）。
  • 第 13 个指针：指向三级间接索引块（索引块中存二级索引块的地址）。

优点：灵活兼顾小文件与大文件（小文件直接访问效率高，大文件通过多级索引扩展容量）。
缺点：访问大文件时需要多次查询索引块，磁盘 I/O 次数较多，效率较低（Ext4 对此做了进一步优化）。

五、空闲空间管理

上述已讨论已占用数据块的存储方式，接下来面临新数据块的放置问题：若逐一扫描磁盘寻找空闲块，效率过低，因此需要引入空闲空间管理机制。常见方法有空闲表法、空闲链表法和位图法。

方法 原理 优点 缺点
空闲表法 记录连续空闲区的起始块和数量 适合少量大空闲区 空闲区多时表巨大，查询慢
空闲链表法 空闲块通过指针串联 简单 无法随机访问，链表操作频繁触发 I/O
位图法 用 1 bit 标记一个块是否空闲（0空闲/1占用） 高效、紧凑 大量小空闲区致表过大，扫描低效

六、文件系统的结构

Linux 用位图管理 inode 与数据块，但单个块组的位图最多管理 128M，故通过引入多个块组（Block Group） 来支撑更大文件系统。

Ext2文件系统结构和块组块组

单个块组内部结构：

  • 超级块（冗余副本）：全局元信息（ inode总数、块总数、单个块组inode数等）。
  • 块组描述符表：各块组的状态信息（空闲块数、inode数等）。
  • 数据位图 与 inode 位图：标记使用情况（是否空闲）。
  • inode 列表：该组内所有 inode。
  • 数据块：实际文件数据。

✍️ 超级块冗余的原因
1.容灾恢复：主超级块损坏时可从副本恢复。
2.性能优化：使文件系统数据与磁盘更近，减少寻道时间。

Ext2 后续版本采用稀疏技术（仅在特定块组存储超级块副本）。

七、目录的存储

目录在 Linux 中同样以文件形式实现，拥有独立的 inode 和数据块。与普通文件不同，目录文件的数据块存储的是子文件/子目录的条目列表（包含文件名、inode 及类型等信息），通过 inode 即可定位到实际文件数据。

目录的存储结构：

  • 列表方式：目录项以线性列表组织，依次存放文件名与 inode 的映射关系（含 . 和 ..）。结构简单，但当文件数量庞大时，线性查找效率较低。
  • 哈希表）方式：ext文件系统采用哈希表组织目录项，对文件名进行哈希计算并存储哈希值，查找时通过哈希快速定位。该方法查找迅速、增删简便，但需处理哈希冲突以保障正确性。
目录哈希表

目录缓存：为减少频繁的磁盘 I/O，内核将最近访问的目录缓存在内存中（即目录项缓存）。

八、软链接与硬链接

在 Linux 中，可通过硬链接（与源文件共享同一 inode）和软链接（独立文件存储目标路径）两种特殊文件来为文件创建别名，两者实现机制迥异。

类型 本质 inode 跨文件系统 删除源文件后
硬链接 目录项指向同一个 inode 相同 不支持 链接仍存在，直到所有链接被删除
软链接（符号链接） 创建新文件（新 inode），内容存目标路径 不同（独立） 支持 链接文件依然存在，但指向的路径无效

九、文件 I/O 分类

1 缓冲 I/O 与非缓冲 I/O

根据是否利用标准库缓冲，文件 I/O 可分为缓冲 I/O 和非缓冲 I/O，主要区别在于数据是否经过用户态缓冲区再传递给内核。

  • 缓冲 I/O：数据先写入标准库缓存，满足条件（如换行）再触发系统调用（减少CPU上下文切换开销）。
  • 非缓冲 I/O：直接调用系统调用（如 read/write），不经标准库缓存。

2 直接 I/O 与非直接 I/O

根据是否利用操作系统的页缓存（Page Cache），文件 I/O 可分为直接 I/O 与非直接 I/O。

  • 非直接 I/O（默认）：数据在用户态与内核缓存间拷贝，由内核决定何时刷入磁盘（异步延迟写入）。
  • 直接 I/O（指定 O_DIRECT 标志）：数据直接经过文件系统访问磁盘，绕过内核缓存。

非直接 I/O 触发刷盘的场景：

  • 内核缓存数据量过大。
  • 用户主动调用 sync / fsync。
  • 内存紧张，无法再分配页面。
  • 内核缓存数据存活时间超时。
