一、I/O 基本概念

1 什么是 I/O？

I/O 即 Input/Output（输入/输出）。程序和数据驻留在内存中由 CPU 执行，当涉及与磁盘、网卡等外部设备的数据交换时，就需要通过 I/O 接口完成。一次完整的 I/O 操作通常经历两个阶段：

  • 等待数据准备：内核等待数据从磁盘/网卡等设备到达内核空间
  • 数据拷贝：将数据从内核空间拷贝到用户空间

根据这两个阶段的不同处理方式，衍生出了多种 I/O 模型。

2 五种 I/O 模型

Linux 下有阻塞 I/O、非阻塞 I/O、I/O 多路复用、信号驱动 I/O 和 异步 I/O 五种经典的 I/O 模型。

五种I/O模型的比较

2.1 阻塞 I/O（Blocking I/O）

用户线程发起 I/O 请求后，进行系统调用，此时用户线程被阻塞，等待内核将数据准备好；内核准备好数据后，将数据从内核空间拷贝到用户空间，返回给用户线程，阻塞结束。

阻塞式I/O模型示意图

类比：去餐厅点餐，站在柜台前一直等到饭做好为止，期间什么也不能做。

2.2 非阻塞 I/O（Non-blocking I/O）

用户线程发起 I/O 请求后，如果内核没有准备好数据，立即返回 error，不阻塞用户线程；用户线程可以重复发起请求进行轮询。当内核准备好数据后，数据从内核空间拷贝到用户空间的过程仍然是阻塞的。

非阻塞式I/O模型示意图

类比：每隔 5 分钟去问一次"饭好了吗"，没好的话就先去干别的事，但取饭时还是要等。

2.3 I/O 多路复用（I/O Multiplexing）

用户线程调用 select/poll/epoll 等函数进行系统调用，内核监视多个文件描述符，用户线程被阻塞；当任何一个描述符的数据准备好后返回，通知用户线程进行读取。

这种方式可以用一个线程同时监听多个 I/O 事件，避免了为每个连接创建一个线程的开销。

2.4 信号驱动 I/O（Signal-driven I/O）

用户线程发起 I/O 请求时，注册一个信号处理函数，然后立即返回继续执行。当内核准备好数据后，通过信号通知用户线程，再由用户线程发起系统调用将数据从内核拷贝到用户空间。

2.5 异步 I/O（Asynchronous I/O）

用户线程发起 aio_read 等异步 I/O 操作后立即返回，不阻塞；内核准备好数据后，自动将数据从内核空间拷贝到用户空间，然后通过信号或回调通知用户线程操作已完成。

类比：点完餐后拿个叫号器，饭好了叫号器会响，直接去取餐即可，全程不需要主动询问或等待。

3 阻塞/非阻塞 与 同步/异步 的区别

维度 含义 关键判断
阻塞/非阻塞 调用者（用户线程）的角度：调用 I/O 函数时是否立即返回 函数是否让进程进入休眠状态
同步/异步 被调用者（操作系统）的角度：I/O 完成后如何通知调用者 数据从内核拷贝到用户空间是否由用户线程完成

💡 重要结论
●阻塞 I/O、非阻塞 I/O、I/O 多路复用、信号驱动 I/O 都属于同步 I/O，因为数据从内核拷贝到用户空间的过程需要用户线程参与并阻塞等待
●只有异步 I/O 模型才是真正的异步，整个 I/O 过程中用户线程没有任何阻塞

非阻塞 I/O 虽然在“等待数据”阶段不阻塞，但在“数据拷贝”阶段仍然阻塞，因此本质上还是同步 I/O

二、异步 I/O 库：libaio 与 io_uring

1 演进背景

传统的同步 I/O（read/write）存在明显的性能瓶颈——线程必须阻塞等待 I/O 操作完成，在高并发场景下会导致严重的资源浪费。

libaio（Linux Asynchronous I/O）于 2002 年引入，首次在内核层面实现了真正的异步 I/O 机制。其核心创新包括异步提交（io_submit）、完成队列回调机制、配合 O_DIRECT 的零拷贝以及批量处理。

随着 NVMe SSD 等高性能存储设备的普及，libaio 的架构缺陷逐渐显现。

io_uring 于 2019 年在 Linux 5.1 中引入，彻底重构了异步 I/O 架构。

2 libaio 的局限

  • 仅支持 Direct I/O：必须使用 O_DIRECT 标志，不能借助页缓存
  • 大小对齐限制：缓冲区大小必须是文件系统块大小的倍数（通常 4KB），且要与内存页大小对齐
  • 可能被阻塞：即使应用层希望异步，某些场景下仍可能被阻塞
  • 拷贝开销大：每个 IO 提交需拷贝 64+8 字节，完成需拷贝 32 字节，共 104 字节
  • 系统调用多：每个 IO 至少需要两次系统调用（submit + wait-for-completion）
  • API 不友好：需要小心处理完成事件以避免丢事件

3 io_uring 的设计与优势

io_uring 的核心设计是一对共享的环形缓冲区（ring buffer），用于应用程序和内核之间的通信：

  • SQ（Submission Queue，提交队列）：应用程序是生产者，内核是消费者
  • CQ（Compeletion Queue，完成队列）：内核是生产者，应用程序是消费者

这种设计带来了三大核心优势：

  • 零拷贝：提交和完成事件无需内存拷贝
  • 零/少系统调用：通过共享内存通信，多数场景无需系统调用
  • 无锁访问：通过内存屏障减少竞争

io_uring 还支持：

  • Bufferred I/O：支持利用页缓存，减少磁盘访问延迟
  • Block 层 Polling 模式：进一步降低延迟
  • 高级特性：链式请求、文件/缓冲区预注册等

io_uring 提供三种工作模式：

  • 中断模式：通过 io_uring_enter 系统调用通知和等待
  • 轮询模式（hipri）：应用主动轮询 CQ 获取完成事件
  • 内核线程模式（sqthread_poll）：内核线程主动轮询 SQ，全程无需系统调用

4 核心 API 对比

操作 libaio io_uring
初始化 io_setup() io_uring_queue_init()
准备请求 io_prep_pread() / io_prep_pwrite() io_uring_get_sqe() + io_uring_prep_read()
提交请求 io_submit() io_uring_submit()
等待完成 io_getevents() io_uring_wait_cqe()
获取完成 io_getevents() io_uring_peek_cqe()
释放资源 io_destroy() io_uring_queue_exit()

5 应用场景

libaio 适用场景：

  • 需要支持旧版内核（< 5.1）的系统
  • 数据库等已经成熟使用 libaio 的存储系统
  • 对 Direct I/O 有明确需求的场景

io_uring 适用场景：

  • 追求极致 I/O 性能的高并发服务
  • 需要同时支持缓存 I/O 和直接 I/O 的场景
  • 大量小 I/O 的场景（避免 libaio 的拷贝开销）
  • 希望减少系统调用和上下文切换的高吞吐场景

性能参考：研究表明，即使是非轮询、非批处理的 io_uring 模式，在所有测试内核上都优于 libaio。在多核 CPU 场景下，io_uring 可以提供接近 SPDK（用户态驱动）的性能。

对比维度 libaio io_uring
内核版本 Linux 2.6+ Linux 5.1+
Direct I/O 必须 可选
Buffered I/O 不支持 支持
系统调用 每个 IO 至少 2 次 几乎为零
内存拷贝 每次 104 字节 零拷贝
对齐限制 严格要求 无要求
性能 基准水平 显著优于 libaio
选型建议：新项目优先考虑 io_uring；若需兼容旧内核（< 5.1），则使用 libaio。

专有名词

[1] HDD（Hard Disk Drive，硬盘驱动器——又称机械硬盘）： 一种传统的数据存储设备，广泛应用于电脑、服务器等电子设备中，用于长期存储数据。它的核心特点是内部包含可旋转的盘片和移动的磁头臂等机械部件，通过物理方式进行数据的读写。
[2] SSD（Solid State Drive，固态硬盘）： 一种基于闪存芯片（Flash Memory）或DRAM芯片的新型存储设备，与传统机械硬盘（HDD）不同，它内部没有旋转盘片和机械臂，所有数据存储和读取均通过电子信号完成，因此称为“固态”。
[3] SATA（Serial Advanced Technology Attachment，串行高级技术附件）： 一种用于连接硬盘、SSD和光盘驱动器的串行总线标准，同时也是一种硬盘物理接口规范。
[4] SAS（Serial Attached SCSI，串行连接SCSI接口）： 一种新一代的SCSI技术，旨在提高存储系统的效能、可用性和扩充性。SAS盘采用串行技术，以获得更高的传输速度，并通过缩短连接线改善内部空间。
[5] AHCI（Advanced Host Controller Interface，高级主机控制器接口）： 一种由Intel主导开发的接口标准，旨在利用SATA硬盘的高级功能，如本机命令队列和热插拔。
[6] PCIe（Peripheral Component Interconnect Express，外围设备组件互联特快）： 一种高速串行计算机扩展总线标准，用于连接计算机主板与各种外部设备。它是继 ISA 和 PCI 总线之后的第三代 I/O 总线，提供了更高的传输速率和更灵活的连接方式。
[7] NVMe（Non-Volatile Memory Express，非易失性内存主机控制器接口规范）： 一种通过PCI Express（PCIe）接口访问非易失性存储设备（如固态硬盘）的技术。相比传统使用SATA接口和AHCI标准的机械硬盘（HDD），NVMe的数据访问速度有了极大的提升。
[8] SPDK（Storage Performance Development Kit，存储性能开发套件）： 一个高性能存储开发工具包，旨在优化存储软件栈，特别是针对NVMe SSD的访问。SPDK的设计理念是通过消除每一处额外的软件开销来提供最少的时延和最高的效率。
